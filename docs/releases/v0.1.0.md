# Fantasma v0.1.0 — experimental release

These notes describe the original tagged release. See [changes on main](unreleased.md)
for subsequent interactive controls, model-selection fixes, and saved sessions.

Fantasma is a configurable framework for AI-assisted security research. This
release introduces an installable CLI and three profile-driven execution styles:
a conversational pentester, coordinated agent teams, and sequential lab workflows.

## Included

- `fantasma` CLI with offline profile inspection and bundled profiles.
- Interactive sessions with conversation context, redirects, scope and stop controls.
- Configurable swarm/lab workflows, models, scoring and coordination mechanisms.
- Python extension hooks and profile-configured MCP tool plugins over stdio,
  Streamable HTTP and SSE.
- Optional authenticated web interfaces alongside terminal interaction.
- Setup guides, examples, generated references, architecture diagrams and tests.

## Install

Python 3.13+ is required. From a checkout of this release:

```sh
git clone --branch v0.1.0 https://github.com/tsirolnik/fantasma.git
cd fantasma
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
fantasma --help
fantasma profiles inspect interactive
```

Configure a model provider before sending requests; see
[Getting started](https://github.com/tsirolnik/fantasma/blob/v0.1.0/docs/getting-started.md)
for browser and Docker setup. The release includes a wheel and source distribution.
It is **not published to PyPI**; plain `pip install fantasma` is not the documented
installation path for this release.

## Known limitations

- Experimental, intended for authorized testing; results need human verification.
- Terminal input currently supports Linux/macOS, not Windows.
- MCP supports tool discovery/calls; OAuth login, prompts, standalone resources,
  and live catalog refresh are not implemented. IDA integration has not been
  validated against an actual IDA server.
- The interactive pentester retains session context but does not automatically
  persist findings to SQLite or run independent validation/reporting.
- Tool operations may have side effects; stopping a run does not undo them.
- Provider compatibility and model availability vary. Automated tests do not
  establish real-world detection quality or production readiness.

The previous command and environment-variable aliases remain accepted for existing
installations. Data paths and profiles are unchanged.
